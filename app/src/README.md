# `quote.ts` — контракт модуля

Документ описує **контракт**, а не реалізацію: що приймають і повертають
експортовані функції, в яких одиницях, що гарантовано і де поведінка не
визначена. Кожне твердження супроводжується посиланням на символ у коді або на
тест, який його доводить.

Перевірено проти поточного стану модуля: `cd app && npm test` — 38 тестів
зелені (2026-09-12).

## Як читати посилання

- Код: `app/src/quote.ts` → `splitInstallments()` — тобто символ (функція, поле
  інтерфейсу, константа), а не рядок.
- Тест: `app/src/quote.test.ts` → тест «ділить $100.00 на 3 платежі без втрати
  цента» — назва цитується дослівно, щоб її можна було знайти пошуком по файлу.
- **Номери рядків не використовуються навмисно.** Попередні версії цього
  документа посилались форматом `файл:рядок`, і посилання з'їхали після першої
  ж зміни коду. Символ переживає редагування сусідніх рядків, номер — ні.

## Навіщо цей модуль

Модуль закриває три кроки роботи з грошима в кошторисі проєкту: порахувати
підсумок за годинами і ставкою з урахуванням знижки (`app/src/quote.ts` →
`estimateTotalCents()`), розбити цей підсумок на платежі
(`app/src/quote.ts` → `splitInstallments()`) і показати суму людині
(`app/src/quote.ts` → `formatMoney()`). Усі суми проходять через нього як цілі
числа в центах — щоб на жодному кроці не з'явилась похибка float
(заголовний коментар `app/src/quote.ts`, поле `QuoteInput.rateCents`).
Головне, що має знати колега: жодна операція тут не губить і не створює цента,
і це закріплено тестами-специфікацією, а не лише коментарями
(`app/src/quote.test.ts` → тести «зберігає суму до цента при будь-якому
розбитті (інваріант)» і «зберігає суму при зворотному розборі рядка
(інваріант)»).

## Правило центів і наслідок передачі не-центів

Правило: **усі суми — цілі числа в центах.** `rateCents` задокументований як
центи, `splitInstallments()` приймає і повертає центи, `formatMoney()` приймає
центи (`app/src/quote.ts` → `QuoteInput.rateCents`, `splitInstallments()`,
`formatMoney()`).

Наслідок передачі не-центів різний для трьох функцій — це не єдина політика, і
на цьому легко обпектись:

| Функція | Не-цілий вхід | Що відбувається | Джерело |
| --- | --- | --- | --- |
| `estimateTotalCents()` | дробові `hours` | штатний, підтримуваний вхід: округлення одне й наприкінці | `app/src/quote.test.ts` → тест «рахує дробові години без втрати пів цента» |
| `estimateTotalCents()` | дробовий `rateCents` | **не відхиляється**: `assertFiniteNonNegative()` перевіряє лише скінченність і знак, дріб тихо зникає в `Math.round`. Тестом не покрито | `app/src/quote.ts` → `assertFiniteNonNegative()`, `estimateTotalCents()` |
| `splitInstallments()` | дробовий `totalCents` | `RangeError` — вхід відхиляється | `app/src/quote.test.ts` → тест «відхиляє неціле число центів на вході» |
| `formatMoney()` | дробові центи | формат ламається (`abs % 100` дає дріб, який вклеюється в рядок). Контрактом не зафіксовано, тестів немає | `app/src/quote.ts` → `formatMoney()` |

Перевірка цілості в `splitInstallments()` — саме `Number.isSafeInteger`, а не
`Number.isInteger`: другий повертає `true` для значень від 2^53, де
цілочисельна арифметика вже неточна і головна гарантія тихо ламається
(`app/src/quote.ts` → `splitInstallments()`; `app/src/quote.test.ts` → тест
«відхиляє суму за межею безпечного цілого замість тихої втрати центів»).

## `estimateTotalCents(input: QuoteInput): number`

Ціна проєкту в центах з урахуванням знижки.

### Одиниці входу й виходу

| Поле | Одиниця | Джерело |
| --- | --- | --- |
| `hours` | години, скінченне число ≥ 0, дробові дозволені | `app/src/quote.ts` → `QuoteInput.hours`, `assertFiniteNonNegative()` |
| `rateCents` | центи за годину (`5000` = $50.00), скінченне число ≥ 0 | `app/src/quote.ts` → `QuoteInput.rateCents`, `assertFiniteNonNegative()` |
| `discountPercent` | відсотки в діапазоні 0..100, необов'язкове, типово `0` | `app/src/quote.ts` → `QuoteInput.discountPercent` і значення за замовчуванням у деструктуризації `estimateTotalCents()` |
| Результат | центи, ціле число в межах безпечного цілого | `app/src/quote.ts` → `Math.round` і перевірка `Number.isSafeInteger` в `estimateTotalCents()`; `app/src/quote.test.ts` → тест «повертає ціле число центів для будь-якого валідного входу (інваріант)» |

### Інваріанти

1. Результат — ціле число центів для будь-якого валідного входу
   (`app/src/quote.test.ts` → тест «повертає ціле число центів для будь-якого
   валідного входу (інваріант)»).
2. Результат лежить у межах `[0, hours × rateCents]` для знижок 0..100
   (`app/src/quote.test.ts` → тест «тримає підсумок у межах [0, години ×
   ставка] для знижок 0..100 (інваріант)»).
3. Монотонність: більша знижка ніколи не дає більший підсумок
   (`app/src/quote.test.ts` → тест «не збільшує підсумок, коли знижка більша
   (інваріант монотонності)»).
4. Нижня межа досяжна: знижка 100% дає рівно `0`, а не від'ємне число
   (`app/src/quote.test.ts` → тест «обнуляє кошторис при знижці 100%»).

### Приклади з реальними числами тестів

```ts
// тест «рахує суму без знижки»
estimateTotalCents({ hours: 10, rateCents: 5000 }); // 50000

// тест «застосовує знижку»
estimateTotalCents({ hours: 10, rateCents: 5000, discountPercent: 10 }); // 45000

// тест «рахує дробові години без втрати пів цента»
estimateTotalCents({ hours: 1.5, rateCents: 4999 }); // 7499
```

### Округлення

Округлення half-up одне й наприкінці: `Math.round` застосовується до вже
здисконтованої суми (`app/src/quote.ts` → `estimateTotalCents()`).

```text
1.5  × 4999  = 7498.5  → 7499
0.25 × 12345 = 3086.25 → 3086
```

Обидва рядки — з `app/src/quote.test.ts` → тест «рахує дробові години без
втрати пів цента».

### Крайові входи

| Вхід | Поведінка | Джерело |
| --- | --- | --- |
| `hours: 0` або `rateCents: 0` | `0` | `app/src/quote.test.ts` → тест «дає нуль, коли нуль годин або нульова ставка» |
| `discountPercent: 100` | `0` | `app/src/quote.test.ts` → тест «обнуляє кошторис при знижці 100%» |
| `discountPercent` відсутній | трактується як `0` | `app/src/quote.ts` → значення за замовчуванням у деструктуризації `estimateTotalCents()` |
| від'ємні `hours` або `rateCents` | `RangeError` | `app/src/quote.ts` → `assertFiniteNonNegative()`; `app/src/quote.test.ts` → тест «відхиляє від'ємні години або ставку замість від'ємного рахунку» |
| `discountPercent` менший за 0 | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє від'ємну знижку замість тихої націнки» |
| `discountPercent` більший за 100 | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє знижку більшу за 100% замість виплати клієнту» |
| `NaN` або `Infinity` у `hours` | `RangeError` | `app/src/quote.ts` → `assertFiniteNonNegative()`; `app/src/quote.test.ts` → тест «відхиляє нечислові значення замість тихого NaN» |
| `hours × rateCents` виходить за безпечне ціле | `RangeError`: кожне значення окремо скінченне, добуток уже ні | `app/src/quote.ts` → перевірка `Number.isSafeInteger` в `estimateTotalCents()`; `app/src/quote.test.ts` → тест «відхиляє кошторис, що вийшов за межі безпечного цілого» |
| дробові `hours` | валідний вхід, округлення на виході | `app/src/quote.test.ts` → тест «рахує дробові години без втрати пів цента» |
| дробовий `rateCents` | не відхиляється, дріб зникає в округленні; тестом не покрито | `app/src/quote.ts` → `assertFiniteNonNegative()`, `Math.round` в `estimateTotalCents()` |

Помилка тут — частина контракту, а не збій: вхід поза діапазоном навмисно
гучний, бо тихий кламп виставив би клієнту рахунок, якого ніхто не замовляв
(коментар над `estimateTotalCents()` у `app/src/quote.ts`; коментар про вибір
`throw` замість клампу в `app/src/quote.test.ts` перед тестом «відхиляє
від'ємні години або ставку замість від'ємного рахунку»).

Текст усіх помилок має єдину форму «X має бути ..., отримано: Y» і будується в
одному місці — `app/src/quote.ts` → `rangeError()`.

## `splitInstallments(totalCents: number, parts: number): number[]`

Розбиває суму в центах на `parts` платежів.

### Одиниці входу й виходу

| Параметр | Одиниця | Джерело |
| --- | --- | --- |
| `totalCents` | центи, ціле число в межах безпечного цілого; може бути від'ємним (повернення коштів) | `app/src/quote.ts` → перевірка `Number.isSafeInteger` в `splitInstallments()`; `app/src/quote.test.ts` → тест «розбиває від'ємну суму (повернення коштів) без втрати цента» |
| `parts` | кількість платежів: ціле число від 1 до 1200 | `app/src/quote.ts` → `MAX_INSTALLMENTS` і перевірка `parts` у `splitInstallments()` |
| Результат | масив рівно з `parts` цілих сум у центах | `app/src/quote.test.ts` → тест «повертає рівно `parts` платежів, кожен — ціле число центів» |

Верхня межа `MAX_INSTALLMENTS` — 1200 (100 років щомісяця). Вона потрібна не
для краси: без неї `4_294_967_296` проходить перевірку «ціле > 0», а далі
`Array.from` кидає сире `RangeError: Invalid array length` замість доменної
помилки (`app/src/quote.ts` → `MAX_INSTALLMENTS`; `app/src/quote.test.ts` →
тест «відхиляє надто велику кількість платежів доменною помилкою»).

### Інваріанти

1. **Головний:** сума всіх платежів точно дорівнює `totalCents` — залишок від
   ділення не губиться і не створюється (`app/src/quote.test.ts` → тест
   «зберігає суму до цента при будь-якому розбитті (інваріант)»).
2. Довжина результату дорівнює `parts`, кожен елемент — ціле число центів
   (`app/src/quote.test.ts` → тест «повертає рівно `parts` платежів, кожен —
   ціле число центів»).
3. Платежі максимально рівні: різниця між найбільшим і найменшим не більша за
   1 цент (`app/src/quote.test.ts` → тест «робить платежі максимально рівними:
   різниця між ними не більша за цент»).
4. Порядок роздачі залишку — **конвенція, а не інваріант**: залишок іде першим
   платежам (front-loaded), і інваріант суми від порядку не залежить
   (`app/src/quote.ts` → `splitInstallments()`, умова `i < Math.abs(remainder)`;
   коментар про конвенцію в `app/src/quote.test.ts` на початку блоку
   `describe("splitInstallments")`).

### Приклади з реальними числами тестів

```ts
// тест «ділить $100.00 на 3 платежі без втрати цента»
splitInstallments(10000, 3); // [3334, 3333, 3333]

// тест «ділить суму із залишком 4 центи, не створюючи зайвих центів»
splitInstallments(100, 6); // [17, 17, 17, 17, 16, 16]

// тест «ділить суму із залишком 2 центи між п'ятьма платежами»
splitInstallments(1002, 5); // [201, 201, 200, 200, 200]

// тест «ділить суму із залишком 3 центи між чотирма платежами»
splitInstallments(999, 4); // [250, 250, 250, 249]

// тест «розбиває від'ємну суму (повернення коштів) без втрати цента»
splitInstallments(-100, 3); // [-34, -33, -33]
```

Як читається front-loaded роздача:

```text
100 / 6 = 16, залишок 4 → перші чотири платежі по 17, решта по 16
```

Джерело рядка вище — `app/src/quote.test.ts` → тест «ділить суму із залишком
4 центи, не створюючи зайвих центів».

### Крайові входи

| Вхід | Поведінка | Джерело |
| --- | --- | --- |
| `totalCents: 0`, `parts: 3` | `[0, 0, 0]` | `app/src/quote.test.ts` → тест «розбиває нульову суму на нулі» |
| `parts: 1` | увесь рахунок одним платежем: `splitInstallments(123457, 1)` → `[123457]` | `app/src/quote.test.ts` → тест «повертає весь рахунок одним платежем, коли частина одна» |
| сума, що ділиться націло | рівні платежі: `splitInstallments(90000, 3)` → `[30000, 30000, 30000]` | `app/src/quote.test.ts` → тест «ділить суму, що ділиться націло» |
| від'ємна сума | симетрично, залишок теж першим платежам: `[-34, -33, -33]` | `app/src/quote.ts` → `step` і `Math.abs(remainder)` у `splitInstallments()`; `app/src/quote.test.ts` → тест «розбиває від'ємну суму (повернення коштів) без втрати цента» |
| `parts: 0` або від'ємний | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє нульову або від'ємну кількість платежів замість тихої втрати суми» |
| дробовий `parts` або `NaN` | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє дробову кількість платежів замість часткового розбиття» |
| `parts` більший за 1200 | доменний `RangeError` з текстом «від 1 до 1200», а не `Invalid array length` | `app/src/quote.test.ts` → тест «відхиляє надто велику кількість платежів доменною помилкою» |
| дробовий `totalCents` | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє неціле число центів на вході» |
| `totalCents` за межею безпечного цілого | `RangeError` | `app/src/quote.test.ts` → тест «відхиляє суму за межею безпечного цілого замість тихої втрати центів» |

Валідація `parts` — це закрита дірка, а не перестраховка. До неї функція мовчки
порушувала власні гарантії: `splitInstallments(100, 0)` повертала `[]`
(зникала вся сума), а `splitInstallments(100, 2.5)` — `[40, 40]` (−20 центів).
Історія зафіксована коментарем у `app/src/quote.test.ts` перед тестом
«відхиляє нульову або від'ємну кількість платежів замість тихої втрати суми».

## `formatMoney(cents: number): string`

Форматує центи в рядок на кшталт `$1,234.50`.

### Одиниці входу й виходу

| Параметр | Одиниця | Джерело |
| --- | --- | --- |
| `cents` | центи, ціле число | `app/src/quote.ts` → `formatMoney()` |
| Результат | рядок виду `$1,234.50`; мінус ставиться **перед** знаком долара | `app/src/quote.test.ts` → тест «ставить мінус перед знаком долара для від'ємних сум» |

Локаль зафіксована як `en-US` у `app/src/quote.ts` → `formatMoney()`
(`toLocaleString("en-US")`): коми між тисячами й крапка перед центами не
залежать від локалі середовища (`app/src/quote.test.ts` → тест «розділяє
тисячі комами у великих сумах»).

### Інваріант

Форматування оборотне: розібравши рядок назад, отримуємо рівно ті самі центи —
без округлення й без втрати знака (`app/src/quote.test.ts` → тест «зберігає
суму при зворотному розборі рядка (інваріант)», допоміжна функція `parseMoney`
у тому ж файлі).

### Приклади з реальними числами тестів

```ts
// тест «форматує центи»
formatMoney(123450); // "$1,234.50"

// тест «додає провідний нуль для сум менших за долар»
formatMoney(5); // "$0.05"

// тест «ставить мінус перед знаком долара для від'ємних сум»
formatMoney(-123450); // "-$1,234.50"
```

### Крайові входи

| Вхід | Поведінка | Джерело |
| --- | --- | --- |
| `0` | `"$0.00"` | `app/src/quote.test.ts` → тест «показує нуль як $0.00» |
| менше за долар | провідний нуль: `5` → `"$0.05"`, `99` → `"$0.99"` | `app/src/quote.test.ts` → тест «додає провідний нуль для сум менших за долар» |
| межа долара | `100` → `"$1.00"` | `app/src/quote.test.ts` → тест «переходить через межу долара» |
| від'ємні | `-5` → `"-$0.05"` | `app/src/quote.test.ts` → тест «ставить мінус перед знаком долара для від'ємних сум» |
| великі суми | `100000000` → `"$1,000,000.00"` | `app/src/quote.test.ts` → тест «розділяє тисячі комами у великих сумах» |
| `-0` | знак не виводиться: перевірка `cents < 0` для `-0` хибна. Тестом не покрито, контрактом не зафіксовано | `app/src/quote.ts` → обчислення `sign` у `formatMoney()` |
| дробові центи | формат ламається: `abs % 100` дає дріб, який вклеюється в рядок. Тестом не покрито, контрактом не зафіксовано | `app/src/quote.ts` → `formatMoney()` |
| `NaN`, `Infinity` | **не визначено**: перевірок у функції немає, тестів немає. Те, що вона поверне, — деталь реалізації, на яку не можна спиратись | `app/src/quote.ts` → `formatMoney()` |

`formatMoney()` — єдина з трьох експортованих функцій, яка свій вхід **не**
валідує: у ній немає ні `assertFiniteNonNegative()`, ні перевірки
`Number.isSafeInteger` (`app/src/quote.ts` → `formatMoney()` проти
`estimateTotalCents()` і `splitInstallments()`). Очищайте вхід до виклику.

## Пастки

Те, на чому легко помилитись, змінюючи модуль:

- **Округлення одне й наприкінці.** `Math.round` застосовується до вже
  здисконтованої суми (`app/src/quote.ts` → `estimateTotalCents()`).
  Округлення на проміжному кроці або заміна на `Math.floor` / `Math.trunc`
  зламає half-up-приклад `7498.5 → 7499` (`app/src/quote.test.ts` → тест
  «рахує дробові години без втрати пів цента»).
- **Кидати, а не клампити.** Спокуса «полагодити» знижку 150% мовчазним клампом
  руйнує контракт: тест очікує саме `RangeError` (`app/src/quote.test.ts` →
  тест «відхиляє знижку більшу за 100% замість виплати клієнту»), і це свідоме
  рішення, а не недогляд (коментар над `estimateTotalCents()` у
  `app/src/quote.ts`).
- **Перевірка підсумку ловить не лише великі числа.** `Number.isSafeInteger`
  над `total` у `estimateTotalCents()` відсікає і нескінченний, і `NaN`-овий
  результат, який виникає, коли добуток `hours × rateCents` переповнюється
  (`app/src/quote.ts` → `estimateTotalCents()`; `app/src/quote.test.ts` → тест
  «відхиляє кошторис, що вийшов за межі безпечного цілого»). Замінити цю
  перевірку на просто `Number.isFinite` недостатньо.
- **`isSafeInteger`, а не `isInteger`, для `totalCents`.** Другий пропускає
  значення від 2^53, де арифметика вже неточна, і головний інваріант суми
  ламається тихо (`app/src/quote.ts` → `splitInstallments()`;
  `app/src/quote.test.ts` → тест «відхиляє суму за межею безпечного цілого
  замість тихої втрати центів»).
- **`Math.abs(remainder)` — не косметика.** Саме він змушує роздачу залишку
  працювати для від'ємних сум (`app/src/quote.ts` → `splitInstallments()`);
  прибрати його — і повернення коштів розсиплеться (`app/src/quote.test.ts` →
  тест «розбиває від'ємну суму (повернення коштів) без втрати цента»).
- **`step` несе знак.** Для від'ємних сум залишок додається як `-1`
  (`app/src/quote.ts` → `splitInstallments()`); жорстко вписаний `+1` зламає
  інваріант суми (`app/src/quote.test.ts` → тест «зберігає суму до цента при
  будь-якому розбитті (інваріант)»).
- **Front-loaded — конвенція, інваріант — сума.** Якщо змінюєте порядок роздачі
  залишку, оновіть точні очікування масивів (тести «ділить суму із залишком
  1 цент без втрати цента», «ділить суму із залишком 4 центи, не створюючи
  зайвих центів», «ділить непарну суму навпіл, віддаючи зайвий цент першому
  платежу» у `app/src/quote.test.ts`), але інваріант суми має лишитись зеленим.
- **`parts` валідується і кидає.** Обчислена кількість частин, що дала `0` чи
  дріб, більше не деградує тихо — вона зупиняє розрахунок (`app/src/quote.ts` →
  `splitInstallments()`). Обробляйте `RangeError` на боці виклику.
- **Верхня межа `MAX_INSTALLMENTS` існує заради доменної помилки.** Прибрати її
  означає повернути сире `RangeError: Invalid array length` з `Array.from`
  (`app/src/quote.ts` → `MAX_INSTALLMENTS`; `app/src/quote.test.ts` → тест
  «відхиляє надто велику кількість платежів доменною помилкою», який звіряє
  текст помилки з «від 1 до 1200»). Зміна числа 1200 змінює текст помилки й
  завалить цей тест.
- **Текст помилок — частина контракту.** Він будується в одному місці
  (`app/src/quote.ts` → `rangeError()`), і тест на межу платежів звіряє саме
  текст, а не лише тип помилки (`app/src/quote.test.ts` → тест «відхиляє надто
  велику кількість платежів доменною помилкою»).
- **Локаль у `formatMoney()` зафіксована навмисно.** Заміна `"en-US"` на локаль
  користувача зламає очікування ком у тисячах (`app/src/quote.ts` →
  `formatMoney()`; `app/src/quote.test.ts` → тест «розділяє тисячі комами у
  великих сумах»).
- **`formatMoney()` розраховує на цілі центи.** `Math.floor(abs / 100)` і
  `abs % 100` не захищають від дробу (`app/src/quote.ts` → `formatMoney()`).

## Потребує уточнення

Питання, на які з коду й тестів відповіді немає, тому контракт по них не
описаний:

- Чи має `formatMoney()` відхиляти нецілі центи, `NaN` та `Infinity`. Зараз
  вона не перевіряє вхід узагалі (`app/src/quote.ts` → `formatMoney()`), і
  тестів на ці класи входу немає. Дві сусідні функції свій контракт
  **виконують** — `formatMoney()` єдина лишилась без нього.
- Чи має `-0` форматуватись із мінусом. Зараз ні (`app/src/quote.ts` →
  обчислення `sign` у `formatMoney()`), тестом ця поведінка не закріплена, тож
  спиратись на неї не можна.
