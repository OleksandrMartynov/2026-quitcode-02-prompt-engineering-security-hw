# Додати тести до модуля

## Роль

Senior TypeScript-розробник, який пише тести як **специфікацію очікуваної
поведінки**. Тест, що описує те, що код робить зараз, — це не тест, а знімок.

## Мета

Покрити вказаний модуль тестами, які виявляють розбіжність між тим, що модуль
**має** робити, і тим, що він робить.

## Контекст

- Модуль: `<шлях до модуля>` — перевірено на `app/src/quote.ts`.
- Наявні тести: `<шлях до тестів>` — перевірено на `app/src/quote.test.ts`
  (навмисно неповні, лише happy path).
- Раннер: `vitest`, запуск `cd app && npm test`. Типи: `cd app && npm run typecheck`.
- Проєкт ESM + `moduleResolution: NodeNext` — імпорти пишуться з розширенням
  `.js` (`from "./quote.js"`), навіть для `.ts`-файлів.
- Домен: грошові суми — **цілі числа в центах**. Операція ділення суми не має
  ні губити, ні створювати копійки.

## Обмеження

- НЕ змінюй продакшн-код. Якщо тест падає — це знахідка, а не привід правити
  реалізацію під тест.
- НЕ послаблюй очікування, щоб отримати зелений прогін.
- Не додавай залежностей, не міняй конфіг раннера, не чіпай інші файли.
- Правити можна лише файл `*.test.ts` поруч із модулем.

## Acceptance criteria

- [ ] Для кожної експортованої функції виписано щонайменше один **інваріант** —
      твердження, яке має триматись для будь-якого валідного входу — і на нього
      є окремий тест. Для функції, що ділить суму на частини, інваріант описує
      зв'язок між входом і **сумою всіх елементів результату**.
- [ ] Є щонайменше 3 тести з входами, де сума **не ділиться націло** на
      кількість частин (різні залишки), і кожен перевіряє результат **цілком**,
      а не лише його довжину чи тип.
- [ ] Покрито межі: `0`, від'ємні значення, відсоток поза діапазоном `0..100`,
      дробові години, кількість частин `1`.
- [ ] **Жодне очікування не підігнане під фактичний вивід коду.** Якщо
      інваріант не збігається з результатом — тест лишається червоним.
- [ ] Кожен тест названий поведінкою («ділить суму із залишком без втрати
      центів»), а не назвою функції («splitInstallments works»).
- [ ] Наведено фактичний вивід `cd app && npm test`: скільки passed / failed і
      назви червоних тестів.

## Формат відповіді

1. Файл тестів цілком.
2. Вивід `npm test` як є.
3. Таблиця падінь: `тест | вхід | очікували | отримали | ймовірна причина (файл:рядок)`.

## Stop

Зупинись, коли тести написані й запущені. Якщо вони червоні — **не чіпай
продакшн-код**, щоб їх позеленити, і не послаблюй очікування: покажи таблицю
падінь і чекай на рішення людини. Не пропонуй рефакторинг і не додавай тестів
на функції, яких у модулі немає.
