# Безпечний рефакторинг

## Роль

Розробник, для якого рефакторинг — це зміна форми при незмінній поведінці.
Якщо поведінка змінилась, це не рефакторинг, а фіча або баг.

## Мета

Покращити будову вказаного модуля, не змінивши жодного спостережуваного
результату.

## Контекст

- Файл(и): `{{шляхи}}` — перевірено на `app/src/quote.ts`.
- Тести як страхувальна сітка: `{{шлях}}` — перевірено на `app/src/quote.test.ts`.
- Мотив рефакторингу: `{{що саме заважає — назви конкретно}}`. Перевірено на
  мотиві «логіка розподілу залишку вбудована в тіло функції й не має імені».
- Команди: `cd app && npm test`, `cd app && npm run typecheck`.

## Обмеження

- НЕ змінюй публічні сигнатури експортованих функцій.
- НЕ редагуй файл тестів. Жодного рядка.
- НЕ додавай функціональності, валідацій чи оптимізацій «поки ти тут».
- Не додавай залежностей.

## Acceptance criteria

- [ ] `cd app && npm test` зелений ДО і ПІСЛЯ, і в обох прогонах **однакова
      кількість тестів** — обидва виводи наведені.
- [ ] `git diff HEAD -- <шлях до тестів>` **порожній** — показати команду і
      вивід (перевірено як `git diff HEAD -- app/src/quote.test.ts`).
      Саме `HEAD`: звичайний `git diff` показує лише unstaged-зміни, тож
      відредагований і доданий у індекс тест виглядав би як недоторканий.
- [ ] `git status --short` не містить нових untracked-файлів (`??`) —
      інакше частина змін лишається поза перевіркою.
- [ ] `cd app && npm run typecheck` без помилок.
- [ ] Сигнатури всіх експортів перелічені до і після — вони збігаються.
- [ ] Кожна зміна має однорядкову причину, прив'язану до `файл:рядок`, а не
      «для читабельності».
- [ ] Жодної нової поведінки: не з'явилось нових кидань помилок і не змінились
      значення для входів, що вже є в тестах.

## Формат відповіді

1. Сигнатури до / після.
2. Діф змін.
3. Вивід `npm test` до і після + вивід `git diff` по тестах.
4. Список змін: `файл:рядок — що зроблено — навіщо`.

## Stop

Один рефакторинг — один прохід. Якщо для зміни доводиться правити тест, це вже
не рефакторинг: зупинись і назви, що саме змінює поведінку. Знайдені по дорозі
баги винеси окремим списком — **не виправляй їх** у цьому ж проході.

## Результат прогону — 2026-09-12

- **Запуск:** `app/src/quote.ts`. Мотив не з голови: після фіксу й рев'ю тестів
  шаблон `«X має бути …, отримано: Y»` розмножився у 5 місцях.
- **Доказ незмінності поведінки — об'єктивний, не на слово:**

  ```text
  npm test ДО:    Tests  35 passed (35)
  npm test ПІСЛЯ: Tests  35 passed (35)     ← та сама кількість
  git diff -- app/src/quote.test.ts          ← порожній (команда прогону)
  git status --short                          ← рівно M app/src/quote.ts
  npm run typecheck                           ← чисто до і після
  ```

- **Понад те, що вимагав промпт.** Агент зняв сигнатури не очима, а емітом
  `.d.ts` (`tsc --declaration --emitDeclarationOnly`) до і після — `diff`
  порожній. І окремо звірив **тексти повідомлень помилок** на 14 невалідних
  входах: усі 14 збігаються побайтово. Тести перевіряють лише
  `toThrow(RangeError)`, тому текст міг тихо змінитись — AC цього не ловив.
- **Stop-правило витримало.** По дорозі знайдено ще один дефект
  (`formatMoney(1.5)` → `"$0.1.5"`, `formatMoney(NaN)` → `"$NaN.NaN"`), і він
  **не виправлений**: фікс додав би нове кидання помилки, тобто змінив би
  поведінку — а це вже не рефакторинг. Винесено списком, як вимагає промпт.
- **Агент виправив мене.** У мотиві я написав «три експортовані функції
  починаються з однакових блоків валідації». Насправді їх дві —
  `formatMoney` валідації не має взагалі. Він відрефакторив те, що є в коді,
  а не те, що я написав в описі.
- **Що довелось поправити в промпті (v1 → v2):**
  1. «Публічні сигнатури ідентичні» — недостатньо: сигнатури можуть збігтись,
     а текст помилки змінитись. Прогін це показав сам, звіривши 14
     повідомлень — тобто AC був слабшим за те, що агент зробив із власної
     ініціативи.
  2. **AC про порожній діф тестів був обхідним.** У прогоні стояло
     `git diff -- <файл>`, а воно показує лише unstaged-зміни: достатньо
     зробити `git add` на відредагованому тесті, і критерій «порожній»
     виконується при зміненому файлі. Виправлено на `git diff HEAD --`
     плюс окрема перевірка untracked-файлів. Дірку знайшов не прогін, а
     розбір зауважень у чужих PR цього курсу.
